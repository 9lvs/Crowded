# iOS app

Native SwiftUI, iOS 17 minimum, MVVM with `@Observable` view models, async/await. Code lives in
`ios/`. The Xcode project is generated from `ios/project.yml` by XcodeGen and is not committed.

## Working with very little disk space
The cloud is the compiler. You do not need Xcode installed to change the app.

1. **Edit anywhere.** Swift files are plain text. Claude can change them in a cloud session.
2. **CI builds and tests every change.** `.github/workflows/ios.yml` runs on GitHub's macOS
   runners for any pull request that touches `ios/`. It generates the project, builds for the
   simulator, and runs the unit and UI tests. Results show on the pull request.
3. **TestFlight puts builds on your phone** once the Apple Developer account exists. No local
   Xcode needed for that either (see below).
4. **Local Xcode is optional.** Use it only for SwiftUI previews or to run on a plugged in phone.

If you do install Xcode locally, keep it small:
- Install Xcode from the App Store or developer.apple.com, then in Settings > Components install
  only the newest iOS simulator runtime. Skip watchOS, tvOS and visionOS.
- Clear build caches when space is tight: `rm -rf ~/Library/Developer/Xcode/DerivedData`.
- Remove simulators you no longer need: `xcrun simctl delete unavailable`.
- Old device support files can be large: `~/Library/Developer/Xcode/iOS DeviceSupport`.

Open the project locally:
```bash
brew install xcodegen
```
```bash
cd ios && xcodegen generate && open Crowded.xcodeproj
```
The first build asks you to trust the OpenAPI generator plugin. Click "Trust & Enable".

## How the code is organized
| Folder | What |
|---|---|
| `App/` | Entry point, `AppModel` (session, timer, theme), `RootView` and tabs |
| `Core/API/` | `CrowdedAPI` protocol, `LiveAPI` (generated client), `MockAPI` (FAKE data), domain models, errors, middleware |
| `Core/Auth/` | Keychain store and `TokenStore` (single flight refresh) |
| `Core/Location/` | One shot location on Report and I'm in line. No tracking |
| `Core/Polling/` | 15 second polling while the app is in the foreground |
| `DesignSystem/` | Tokens, typography, theme, components, component gallery (debug) |
| `Features/` | Onboarding, Tonight, BarDetail, Report, LineTimer, Settings, Staff |

## API client (decision)
The client is generated by Apple's swift-openapi-generator from the backend contract. The iOS
copy `ios/Crowded/API/openapi.json` is made by `ios/scripts/sync_openapi.sh` from
`docs/openapi.json`, with three normalizations so the generated Swift is simple and forward
compatible:
- `anyOf [T, null]` becomes an optional `T`.
- `format: uuid` and `format: date-time` become plain strings. The app parses dates itself, with
  or without fractional seconds.
- `additionalProperties: false` and string `enum` lists are dropped, so a newer server that adds a
  field or a value never breaks an older app. Domain enums fall back safely.
- Numeric bounds (`minimum`, `maximum`) are dropped. Pydantic writes integer bounds as floats,
  and the server validates them anyway.

After any backend API change run `ios/scripts/sync_openapi.sh`. CI fails if the copy is stale.
Only `Core/API/LiveAPI.swift` touches generated types. Views use domain models only.

## Security and privacy (MASVS notes)
- Refresh token in the Keychain only (`AfterFirstUnlockThisDeviceOnly`). Access token in memory.
  Nothing sensitive in UserDefaults (only the theme preference).
- App Transport Security stays on. Release builds talk HTTPS only. Debug talks to localhost,
  which ATS allows by default.
- Location: `WhenInUse` only, one `requestLocation()` per action with a timeout, no background
  modes. The server keeps only "near the bar" and a distance bucket.
- Privacy manifest: `Resources/PrivacyInfo.xcprivacy`. No tracking.
- No certificate pinning in v1 (docs/DECISIONS.md D-011).

## Run modes
- Normal: talks to `CROWDED_API_BASE_URL` from `ios/Config/*.xcconfig`.
- `-mockAPI` launch argument: FAKE in memory data, no server. Used by UI tests and demos. In Xcode:
  Product > Scheme > Edit Scheme > Run > Arguments.

## Once the Apple Developer account exists
1. Create the App ID `app.crowded.ios` (or your final bundle id) at developer.apple.com.
2. Put your team id in `ios/project.yml` (`DEVELOPMENT_TEAM`) or set it in Xcode once.
3. In App Store Connect create the app record (name, bundle id, SKU).
4. Xcode Cloud (25 free compute hours a month with the program): in App Store Connect, Xcode
   Cloud, create a workflow for this repo that archives the `Crowded` scheme on pushes to `main`
   and distributes to TestFlight. Add `ci_scripts/ci_post_clone.sh` running
   `brew install xcodegen && cd ios && xcodegen generate` (Claude can add this).
5. TestFlight internal testing first (your team, no review), then external testing with a
   public link (needs Beta App Review). The public link is what goes in the Instagram bio.
6. Turn on Sign in with Apple: add the capability, set `CROWDED_SIWA_ENABLED = YES`, and wire
   the button (stubbed today).
